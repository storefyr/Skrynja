# M0.0 — Målerapport: Findes `vibe-acp` som modpart for Skrynja?

**Dato:** 2026-10-26
**Revideret:** 2026-10-26 (efter præcisering: vejkortet bygger ACP-klienten, ikke agenten)
**Målmaskine:** Jolla Phone (2026), Sailfish OS 5.x, aarch64 — **kun klienten (L1)**
**Målemetode:** Web-research (ingen kodeændringer, ingen API-kald)
**Lag:** L3 (agentens eksistens som modpart)

---

## Spørgsmål (fra vejkortet §8)

> Findes `vibe-acp` på målmaskinen, i hvilken version, under hvilken licens?

## Præcisering af vejkortets tre lag

Vejkortet §1 og §2 er eksplicit: **Skrynja er ACP-klienten (L1)**. Vejkortet er
*ikke* en implementeringsplan for agenten — det er en kontrakt- og måleplan for
klienten. `vibe-acp` er **modparten (L3)** som Skrynja skal kunne tale med.

| Lag | Hvad | Hvor kører det |
|---|---|---|
| **L1** | Skrynjas protokollag (det vi bygger) | Jolla Phone (2026), aarch64, C++/Qt 5.6 |
| **L2** | Transport (stdio / HTTP-bro / WebSocket) | Mellem telefon og agent |
| **L3** | `vibe-acp` (modparten) | **Ikke nødvendigvis på telefonen** |

M0.0 spørger derfor ikke "kan telefonen køre vibe-acp?" — det spørger
"findes der en vibe-acp at måle på, og under hvilke betingelser kan Skrynja
tale med den?"

## Resultat: JA — `vibe-acp` findes, men IKKE på Sailfish OS

### Hvad findes

| Egenskab | Værdi | Kilde |
|---|---|---|
| Projekt | `mistral-vibe` (indeholder `vibe-acp`) | github.com/mistralai/mistral-vibe |
| Seneste version | v3.0.2 (pyproject.toml, okt 2026); vejkortet observerede v2.26.1 | pyproject.toml hentet 2026-10-26 |
| Licens | **Apache-2.0** | pyproject.toml |
| Sprog | Python ≥ 3.12 | pyproject.toml `requires-python` |
| ACP-protokol | `agent-client-protocol==0.11.0` (Python SDK) | pyproject.toml dependencies |
| Transport | JSON-RPC 2.0 over **stdio** (standard ACP) | ACP-spec, DeepWiki |
| Platforme | Linux, macOS (UNIX officielt targeteret); Windows sekundært | README, docs.mistral.ai |
| Distribueres som | PyPI-pakke (`pip install mistral-vibe`), `uv tool install`, selvstændig binær | PyPI, Mistral Docs |

### Hvad findes IKKE

- Ingen Sailfish OS-pakke (hverken Jolla-repo, OpenRepos eller Chum)
- Ingen aarch64-Sailfish wheel eller binær
- Ingen præbygget binær til mobil Linux overhovedet

### Kan vibe-acp køre på telefonen? — Nej (ikke relevant for vejkortet, men noteret)

| Problem | Detalje |
|---|---|
| Python-version | Kræver ≥ 3.12; Sailfish OS har ≤ 3.11 (3.11 merged nov 2025, ikke bekræftet udrullet) |
| Afhængigheder | ~90 pakker, mange med native C/Rust-extensioner (pydantic-core, cryptography, tree-sitter, rpds-py, zstandard) |
| Byggesystem | Maturin + Rust extension (`mistralai_vibe_local_harness._native`) |
| Harbour | Appen skal bundle alle Python-libs; ingen pip ved install; Sailjail sandbox blokerer fil/shell-adgang |
| Størrelse | 100-300+ MB mod Harbour's anbefaling |

**Konklusion:** Lokal agent på telefonen er ikke realistisk — men det er heller
ikke vejkortets mål. Vejkortet bygger klienten.

## Hvad M0.0 betyder for vejkortet

M0.0 er **ikke en blokering** — det er en **afklaring**:

1. **`vibe-acp` findes og er målelig** — den kører fint på Linux/macOS/PC.
   Skrynja kan måle den (M0.1–M0.14) fra en udviklingsmaskine eller en
   ekstern server før klienten færdiggøres.

2. **Transportvalget (A2) bliver afgørende.** Vejkortets Trin B lister tre
   kandidater:
   - **Direkte stdio** — kræver lokal underproces → ikke mulig på telefonen
   - **HTTP-bro** (`agent-client-protocol-http` som broker) — mulig over netværk
   - **Egen bro** — Skrynja implementerer selv HTTP/WebSocket-klient

   Da telefonen ikke kan køre agenten lokalt, er **stdio udelukket**.
   Tilbage står HTTP/WebSocket til en ekstern agent.

3. **Teststrategi:** M0.1–M0.14 (som måler agentens adfærd) kan udføres
   fra en PC med `vibe-acp` installeret — ikke fra telefonen. Telefonen
   behøver kun at kunne *tale* ACP, ikke at køre agenten.

4. **A7 (sprog- og kørselsvalg)** skal besvare: Kan Skrynja (Qt 5.6 C++)
   implementere en ACP-klient over HTTP/WebSocket uden ekstra afhængigheder?
   (Qt 5.6 har QNetworkAccessManager og QWebSocket — dette skal verificeres.)

## Anbefaling: Fortsæt vejkortet med justeret transport

| Trin | Justering |
|---|---|
| A2 (transportvalg) | stdio udelukket. Vælg mellem HTTP-bro og egen WebSocket/HTTP-klient. M0.16 måler om `agent-client-protocol-http` kan køre foran en ekstern vibe-acp. |
| A7 (sprog/kørsel) | Verificer at Qt 5.6 QNetworkAccessManager + QWebSocket er tilstrækkelige til ACP over netværk. Ingen Python påkrævet. |
| B1–B6 | Omskriv fra stdio til netværkstransport. |
| M0.1–M0.14 | Udføres fra PC med vibe-acp — ikke fra telefonen. |
| M0.15 | Verificer at Skrynja kan bygges uden ACP Rust SDK (klienten er C++, ikke Rust). |
